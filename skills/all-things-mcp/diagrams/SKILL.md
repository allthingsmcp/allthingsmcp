# All Things MCP diagrams

Read `references/diagram-language.md` before creating or revising a diagram. Read the relevant official MCP specification source before asserting protocol behavior.

## Workflow

1. State the teaching question the diagram must answer.
2. Choose the smallest valid form: topology, request flow, sequence, state, or comparison.
3. Use official entity names and separate protocol facts from implementation examples.
4. Reuse the node taxonomy and semantic colors.
5. Label every non-obvious edge and include a compact legend when multiple line styles appear.
6. Make reading order explicit, left-to-right on desktop and top-to-bottom on mobile.
7. Provide equivalent text for accessibility.
8. Verify terminology and behavior against the recorded specification version.

Run the focused authoring checks before opening a pull request:

```bash
pnpm format:write
pnpm content:validate
pnpm typecheck
pnpm lint
```

The content validator rejects invalid metadata, duplicate slugs, missing Guide steps, mismatched step order, broken internal references, unapproved MDX components, imports, exports, and executable JavaScript.

## Preview the complete experience

```bash
pnpm dev
```

Open the Guide overview and every step. Check both a desktop viewport and a narrow mobile viewport.

## Prepare the pull request

Keep the pull request focused on one Guide. Explain its intended reader, promised outcome, verification environment, and any parts that need especially close technical review.

<Callout title="Technical review is part of publication" type="warning">
  Do not change `status` to `published` merely because the page builds. A
  maintainer must review the writing and a technically qualified reviewer must
  verify claims, commands, and version scope.
</Callout>

When review is complete, add `publishedAt`, update `lastVerified`, change the status to `published`, and rerun the checks.

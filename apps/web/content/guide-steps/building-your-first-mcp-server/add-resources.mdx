Resources expose read-only data that the host application can retrieve and attach as context. A resource needs a stable URI, useful metadata, and a content type the client can interpret.

Select **Supported cities** and inspect its `weather://cities` URI and response shape before adding it. You can compare it with the other curated resources first.

<InteractiveGuideBlock scene="add-resources" />

<Callout title="Resources are not tools">
  Use a resource for data a client reads. Use a tool for an operation that the
  model may choose to invoke. The distinction helps hosts apply appropriate
  presentation and approval policies.
</Callout>

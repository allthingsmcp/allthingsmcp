Your server starts with a name and nothing else. Over the next three steps you'll add what it offers. Creating it also starts a **workspace**: a hosted copy of your server that answers real MCP requests, so you can test it before you download anything.

## 1. Name your server

Use a short, lowercase, hyphenated name. The default, `weather-server`, says what the server does and works as a package name when you export the project.

<InteractiveGuideBlock scene="create-server" />

The name isn't just a label for this guide. Every response your server sends identifies it in `_meta`, so any client that connects can show you which server it's talking to:

```jsonc
"_meta": {
  "io.modelcontextprotocol/serverInfo": {
    "name": "weather-server", // the name you chose
    "version": "0.1.0",
  },
},
```

You'll see this block in step 6, at the end of every response in the **Protocol** tab.

<Callout title="A temporary real workspace">
  Creating the server starts a seven-day workspace that executes real MCP
  requests. Sign in to claim it and issue credentials for its external endpoint.
</Callout>

## 2. Read the generated code

Switch to the **Code** tab. The guide writes a complete TypeScript server as you work, using the official MCP TypeScript SDK. Right now its core looks like this:

```typescript title="src/server.ts"
function buildServer() {
  const server = new McpServer({
    name: 'weather-server',
    version: '0.1.0',
  });

  // Add tools, resources, and prompts here.

  return server;
}
```

`McpServer` holds your server's identity and everything it offers. Further down, the file wraps `buildServer` in an HTTP handler, so the server answers MCP requests at a single `/mcp` URL. You'll run that file yourself in step 8.

**Checkpoint:** the **Code** tab shows `new McpServer` with your server's name and the comment `// Add tools, resources, and prompts here.` The server exists but offers nothing yet.

Some `tools/call` requests take time to finish. A large batch may keep running,
or a workflow may pause for approval. **Tasks lets an MCP server return a task ID
so the MCP client can follow the work and retrieve its result later.**

This guide assumes you have built an MCP server and are new to Tasks. You will
implement the extension on both an MCP server and an MCP client, using an image
batch to exercise the lifecycle.

## What you will build

Your MCP server will use Sharp to turn six images into **eighteen thumbnails**:
three widths per image. Your MCP client will start the batch, report its status
and retrieve the output location. Then you will reconnect using a saved task ID
and try cancellation.

![Three generated sample images resized to 320 pixels wide: landscape, portrait and square.](/images/guides/mcp-tasks-thumbnails.png)

We will use polling and a local task store. Approval prompts and pushed status
notifications are outside this first walkthrough. Small images finish quickly,
so a labelled demo delay will make the running state easier to observe.

Start with **Understand when Tasks help** below.

## Use standard Markdown first

Ordinary Markdown keeps contributions readable in GitHub and portable outside the site. Writers can use:

- second- and third-level headings
- **bold** and _emphasis_
- [descriptive links](https://modelcontextprotocol.io/)
- ordered and unordered lists
- inline `code`
- fenced code blocks with a language
- blockquotes for short quotations or principles
- tables for compact comparisons

## Give the step a reliable rhythm

1. Explain what the reader is about to do and why.
2. Show the exact command, code, or interface action.
3. Explain only the details that affect the result.
4. Provide a checkpoint the reader can observe.
5. Identify likely failure modes when they are consequential.

<Callout title="One step, one meaningful result" type="note">
  A step may contain several small actions, but they should all resolve one
  named part of the Guide. Split a step when it creates a separate artifact or
  requires a separate verification loop.
</Callout>

A useful test crosses the protocol boundary. Choose a location, invoke the first configured tool, then inspect both the result and the corresponding `tools/call` exchange.

<InteractiveGuideBlock scene="test-server" />

<Checklist
  items={[
    'The ATM client discovered the server before invoking a tool',
    'The request names a configured tool',
    'Arguments match the tool input schema',
    'The response contains both text and structured content',
  ]}
/>

The weather value is deterministic, so repeating the same request produces the same result. That makes the Guide useful without presenting a simulated upstream API as real.
